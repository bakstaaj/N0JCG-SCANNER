# PI P25 Scanner backend systemd service

V0.2D adds a guarded Raspberry Pi systemd service workflow for running the PI P25 Scanner web/API backend on boot.

The service runs only the backend and web UI on port `8070`. It does not bypass the validated OP25 launch gate. Scanner Start still requires the ignored runtime marker created by the bounded live command probe:

```text
runtime/settings/op25_validated_rx_command.env
```

## Dry run

From the Raspberry Pi repository root:

```bash
cd ~/scanner
./tools/pi5_p25_backend_service_install.sh --dry-run
```

The dry run writes a unit preview under `.p25_backend_service_reports/` and makes no system changes.

## Install and start on boot

```bash
cd ~/scanner
./tools/pi5_p25_backend_service_install.sh --install --yes
./tools/pi5_p25_backend_service_probe.sh
```

Open the UI at:

```text
http://<pi-ip>:8070
```

## Service controls

```bash
sudo systemctl status pi-p25-scanner.service
sudo systemctl restart pi-p25-scanner.service
sudo systemctl stop pi-p25-scanner.service
```

## Uninstall

```bash
cd ~/scanner
./tools/pi5_p25_backend_service_install.sh --uninstall --yes
```

## Safety guardrail

This service exposes the existing backend and UI. Encrypted P25 calls remain out of scope for decoding. The OP25 launch path remains restricted to the command marker generated by the validated live-command probe.
